소개
다양한 프로그래밍
이른바 「프로그래밍」을 실시하는 환경이나 언어에는 여러가지가 있습니다.

CPU를 대상으로 Rust/Python/C++와 같은 언어로 프로그래밍
GPU를 타겟으로 CUDA/SYCL/GLSL 등의 언어로 실시하는 프로그래밍
Programmable Logic을 대상으로 HLS / SystemVerilog / VHDL / Chisel과 같은 언어로 프로그래밍
둘 다 각각 좋고 나쁜 즐거운 프로그래밍 세계이며 모든 언어로 튜링 완전한 프로그래밍이 가능하다는 점에서 모든 계산을 작성할 수 있습니다.
그 중에서도 이번은 KV260을 사용한 Programmable Logic에서의 프로그래밍 이야기입니다.

여기서 이번 소재로 하는 AMD(Xilinx)의 ZynqMP 라는 프로세서는 APU(Cortex-A53), RPU(Cortex-R5), GPU(Mali-400), PL(Programmable Logic)이 모두 들어간 프로세서이며, 이들을 연계시켜 이용할 수 있습니다.

다양한 프로그래밍을 즐길 수 있습니다.

라는 매우 매력적인 프로세서 입니다.

PL (Programmable Logic) 프로그래밍
Programmable Logic에 대한 프로그래밍은 더욱 커집니다.

HLS와 같은 고위 합성 툴을 사용한 데이터 흐름 수준에서 프로그래밍
SystemVerilog/VHDL/Chisel 등을 이용한 RTL(Register Transfer Level)이라는 사이클 단위의 거동을 기술할 수 있는 프로그래밍
2 종류가 있습니다.

HLS 개발은 여러 곳에 정보가 있으므로, 여기서는 KV260 RTL 프로그래밍을 SystemVerilog 를 사용해 실시하는 방법의 최초의 한 걸음에 대해 소개하고 싶습니다.

RTL 프로그래밍의 적절한 영역으로는

CPU나 캐시 시스템 등 독자적인 프로세서를 만드는 등
독자적인 AI 엔진이나, Video 코덱 등으로, 고효율의 엔진 블록을 만드는 등
이미지 센서, LCD, 모터 등 외부 장치와의 인터페이스 프로그램
사이클 단위로 타이밍 제어하고 싶은/동기화하고 싶은 실시간 어플리케이션
등등 여러가지 분야가 있습니다.

블록 디자이너를 사용하여 PS에서 클럭을 추출
KV260은 PL (Programmable Logic)에 연결된 외부 핀에 클럭이 없습니다.
그러나 클럭에 동기하여 움직이는 로직을 기술하는 RTL 프로그래밍에서는 먼저 클럭이 필요합니다.

그렇다면 PS(Processor System)에서 클럭을 받는 것이 필요합니다.

이런 부분이 자주 첫눈에 울게 될지도 모르기 때문에, 제대로 설명해 갑니다.

물리적으로 ZynqMP의 LSI는 PS와 PL의 두 부분으로 나뉩니다.
PL은 LSI의 일부일 뿐이지만, PL의 프로그래밍상의 개념으로서는,

" LSI 전체 안에 우선 PL이 있고 그 안에 PS가 있다 "

라는 프로그래밍 모델이므로주의가 필요합니다.

그러므로, RTL 프로그래밍 속에서 정의하는 1 모듈로서 PS가 등장합니다.

다음으로 Vivado에는 Block Designer라는 미리 준비된 코어를 GUI로 연결하여 프로그래밍하는 도구가 있습니다.
지금 유행의 로우 코드 개발이라고 말할 수 없지만, 「RTL 프로그래밍을 즐긴다」가 본 기사의 목적입니다.
한편, PS에서 클럭을 꺼내는 것만으로 사용하기에는 매우 편리한 툴이므로, 여기만은 Block Designer 를 사용하기로 합니다.

바로 아래와 같은 LED를 점멸시키는 프로그램을 써 보았습니다.

덧붙여 코멘트는 일본어로 쓰고 있습니다만, Vivado의 에디터라면 일본어는 문자화할 수 있다고 생각하므로 나쁘지 않고 양해 바랍니다.

여기서 처음으로 「Verilog의 책으로 공부한 세계」가 됩니다. 교과서에 쓰여 있는 것을 교과서대로 하려고 하면, 그 전 단계에 여러 가지 있는 것입니다.

`timescale 1ns / 1ps

module top(
        output  var logic   [0:0]   led     // LED用に出力を 1bit 定義
    );

    // ブロックデザインからクロックを引き出す
    logic   clk;
    design_1 i_design1(.pl_clk0_0(clk));

    // クロックで動作する26bitのカウンタを作成
    logic   [25:0]  counter = 0;
    always_ff @(posedge clk) begin
        counter <= counter + 1;
    end

    // カウンタの25bit目をLEDに出力
    assign led = counter[25];

endmodule

조금, 해설해 두면. 방금 블록 디자이너에서 만든 블록을 design_1이라는 이름으로 이용하고 있습니다. 방금 만든 pl_clk0_0이라는 포트에서 시계를 검색했습니다. 초기 상태에서 100MHz가 공급됩니다.
그 후, 26bit의 카운터 변수를 정의해, 클럭의 상승의 정도로 인크리먼트 하고 있습니다. 마지막으로 led 포트에 카운터의 25bit째의 0 or 1 을 출력하고 있습니다. 카운터가 오버플로되면 0으로 돌아가므로 led는 깜박임을 반복해야합니다.

이것으로 Verilog 교과서에 쓰여진 이야기는 끝납니다.

이후는 이 프로그램이 실기로 움직이도록 해 갑니다.

"LED의 포트가 어디에 연결되는지 아직 아무 설정도 하지 않은 것은?"

Programmable Logic 의 컴파일은, 논리 합성(Synthesis)과 배치 배선(Implementation)의 2 단계로 행해집니다만, 논리 합성까지는 「실제로 LED가 무엇번 핀에 연결되고 있는 것인가?」등의 정보는 불필요하므로, RTL로서 올바른 소스 코드가 되어 있으면 논리 합성을 실시할 수 있습니다.

C/C++ 에서의 임베디드 프로그램 개발로, 메모리 맵(링커 스크립트)을 주지 않아도 소스 단체의 컴파일만은 할 수 버리는 것과 비슷하네요.

논리 합성 (Synthesis)을 수행하려면 F11을 누르거나 툴바에서 Run Synthesis를 선택하십시오.

Run Synthesis

LED 출력의 배선 확인
그런데, 방금전, 「H12」, I/O Std 에 「LVCMOS33」이라고 하는 설정을 했습니다만 어떤 일입니까?

먼저 자일링스 사이트에서 KV260 회로도를 다운로드 할 수 있으므로 살펴 보겠습니다.

이번에는 KV260의 PMOD(J2)의 1번 핀과 GND인 5번 핀 사이에 LED와 저항을 직렬로 연결되도록 브레드보드를 ​​결선하고 있습니다.

PMOD 회로도

회로도를 보면 J2의 1번 핀은 PMOD_HDA11이라는 신호명입니다.
쫓아 가면 R276을 통해 HDA11이라는 신호 이름으로 바뀐 후 SOM240_1의 A17 핀에 연결되어 있음을 알 수 있습니다.

SOM240_1 회로도

여기부터 K26 SOM 모듈이지만, 현재로서는

K26 SOM 모듈 회로도는 공개되지 않음
Vivado 도구는 K26 SOM 핀이 아닌 모듈의 ZynqMP LSI 핀을 지정합니다.
라는, 조금 귀찮게 되어 있습니다.

AMD(Xilinx)로서는, K26 SOM 을 모듈로서 상품으로 하고 싶은 것 같습니다.

그러므로 이 문서에서 XTP685 - Kria K26 SOM XDC File (v1.0)을 찾아서 유명한 뒤 다운로드해 옵니다.

XPT68 사진 31

그리고 다운로드 한 xdc를 검색하면 som240_1_a17이 H12 핀임을 마침내 알 수 있습니다.

그런 다음 H12 핀의 I / O 설정을 어떻게해야하는지 확인하십시오.

다운로드 한 XTP685 파일에서 H12는 I / O 뱅크 45에 속하며 VCCO는 som240_1_b13에서 공급되고 있음을 알 수 있습니다.

그리고 다시 회로도로 돌아오는 것으로 PL_3V3(3.3V)가 공급되고 있는 것을 알 수 있군요.

회로도 B13

I/O 핀의 설정은 VCCO의 전압에 따라 선택할 수 있는 것이 정해져 옵니다만, LED의 점멸을 시키면 단순한 디지털 레벨로 H/L의 제어를 할 수 있으면 되므로 LVCMOS33을 설정하고 있습니다.

이것으로 출력값이 0일 때는 0V, 출력값이 1일 때는 3.3V가 출력되며, 전류값으로는 최대 16mA까지 흘릴 수 있습니다.

자주 전자 공작으로 보이는 전통적인 빨강이나 초록 등의 LED의 순방향 전압이 대체로 2.1V라든지이므로

(3.3V - 2.1V) / 100Ω = 12mA

이므로, 16mA의 드라이브 능력으로 어떻게 든 계산입니다.

결론
여력이 있으면 xsim에서의 시뮬레이션이나 ILA를 사용한 실기 디버그의 이야기도 쓰고 싶었습니다만, 힘이 다했으므로 이번은 여기까지입니다.

Verilog등의 교과서를 보고 프로그래밍 언어를 이해해도, 막상 움직이려고 하면 언어 이외에 기억해야 할 것이 많이 있을까 생각합니다.

KV260과 같이 다운로드한 Ubuntu 이미지를 SD카드에 쓰는 것만으로 기동하는 보드가 나온 덕분에 ZynqMP를 IoT 프로그래밍 플랫폼으로 선택할 때의 점착성이 현저히 높아진 것 같아요.
한편, "Ubuntu는 시작했고, Verilog 등의 RTL 프로그래밍의 입문서도 읽기 시작하고 있어"라는 쪽이, "어떻게 이 RTL의 코드 움직이면 좋을까?"가 되어 버렸을 때에 L치카는 최초의 한 걸음으로서 매우 중요하다고 생각합니다.

반대로 L치카를 확실히 이해하면, 단자를 늘려 실제로 여러가지 RTL을 프로그램하면서 배워 가는 것이 가능하게 되는 것은 아닐까요.
